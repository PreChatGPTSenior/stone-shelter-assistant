# Agent instructions

- This is a learning application. Read [project overview](docs/project-overview.md) and [setup](docs/setup.md). Keep the focus on understanding search and evaluating experiments; production completeness is outside the current scope.
- The owner is an experienced Java developer learning Python and AI workflows. Edit application code or tests only when asked; explain relevant decisions plainly. Discuss work in Russian and write repository text, code comments and commits in English.
- Support current contracts only. Do not add backward compatibility, legacy DTOs, old-format adapters or tests preserving obsolete schemas. Update current callers and fixtures together. Frozen experiment records remain historical data without runtime compatibility support.
- Active questions, prompts, fixtures and names are English-only. Future translation must retain original evidence and spans; do not implement it without a selected task.
- The four knowledge sources deliberately contain contradictions. Preserve exact quotes, source IDs, individual/type scope and agreement scope. PostgreSQL is authoritative for current availability; do not derive it from event history. Do not silently repair unsupported parses or weaken source validation to make a scenario pass.
- Keep feature code in `stones`, `search` and `assistant`; shared infrastructure belongs in `core`, application assembly at the package root. Separate document preparation from backend calls. Use typed, idiomatic Python and explicit ORM relationship loading.
- Authored stone/knowledge data belongs in `fixtures`. Test-only inputs and frozen experiment records belong in `tests/fixtures`. Preserve successful and failed run records with their inputs, settings and hashes.
- Automated database/search tests use disposable Testcontainers, never persistent local services. Do not delete local data or volumes without an explicit request. Paid model runs, commits and pushes require explicit authorization; respect run limits.
- Keep documentation minimal: one current project overview and a practical setup guide. Do not recreate ADR series, task logs, roadmaps or duplicate architecture documents. Keep dataset provenance and experiment records with their fixtures. Before a commit, verify that the overview/setup still match the actual change and report only observed checks.
- Never create, edit, move, rename or delete the root `README.md` unless the owner explicitly requests that file. The owner maintains it.
- Keep searches and tool output short. Prefer `rg`; run checks appropriate to the change. Do not read or print local secret values.
