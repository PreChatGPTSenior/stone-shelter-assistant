## ADDED Requirements

### Requirement: Reusable operational examples
The pilot corpus SHALL reuse consistent single-stone registration requests with required case, source-owned current status, optional profile and ADMITTED evidence; it SHALL preserve existing UUIDs for unchanged examples.

#### Scenario: Prepare a profile-based search example
- **WHEN** an existing fixture already contains the required profile and history
- **THEN** the corpus references that fixture rather than creating a duplicate stone or rewriting its current state from events

### Requirement: Source inventory
The source inventory SHALL distinguish operational records, the encyclopedia and fictional JSON type compatibility, recording paths and illustrative questions without claiming measured relevance.

#### Scenario: Review pilot source coverage
- **WHEN** the two reference sources and operational examples have been authored
- **THEN** a reviewer can find each source and a question it can support, including its fictional or geological scope
